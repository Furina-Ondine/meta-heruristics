# SPEC-0010：随机采样 SIMD 化

## 元数据

- 编号：`SPEC-0010`
- 状态：`Approved`
- 创建日期：2026-09-06
- 批准人：项目作者
- 批准日期：2026-09-06
- 替代：替代 SPEC-0009 中单组四字状态及排除内部多流/Jump 的限制；其他公共随机契约继续有效
- 被替代：无
- 相关 ADR：ADR-0014、ADR-0019、ADR-0021

## 问题与动机

基于提交 `819a40c` 的调查：`RandomSource.Fill` 已将四个状态字局部化，但仍逐个执行 xoshiro256++；`StandardNormal.Fill` 仍逐对调用标量 Log/Sqrt/Cos/Sin。批量 API 已就绪，尚未证明 SIMD 候选能降低采样或算法整体耗时。单流的连续状态存在依赖，不能将相邻输出直接当作独立 SIMD lane 推进。

## 目标

- 在现有封闭随机源内实现原始 xoshiro256++ 状态推进的 SIMD，并验证批量转换、区间映射和标准正态计算的增量收益。
- 区分原始状态推进、输出转换和分布运算的收益，不以批量方法命名作为 SIMD 已实现的证据。

## 非目标

- 不新增第二 PRNG，不公开子流、Jump、状态导入导出、公共后端或随机工厂；允许为 SIMD 在 RandomSource 内部建立私有 lane 状态。
- 不在 Core 修改算法抽样布局；四种算法分别由 SPEC-0011 至 SPEC-0014 管理。
- 不重新引入 Reflect SIMD，不将生成器接入 Core。

## 架构契合

保留 Core Randomness 的唯一职责和 xoshiro256++ 1.0 算法，把单组四字状态调整为 run 私有的多 lane 四字状态。每个 lane 独立执行同一状态转换，SIMD 同时推进多个 lane，而非把单条流连续输出误当成独立输入。

采用 SplitMix64 从 run seed 初始化首个 lane，再用作者参考 Jump 派生其余 lane，起点间隔为 2^128 次状态推进。该间隔用于约束 lane 子序列，不能作为统计独立性或不同 run seed 之间不重叠的证明。内部 Jump 只参与播种，不成为公共 API。参考：[作者 xoshiro256++ 实现](https://prng.di.unimi.it/xoshiro256plusplus.c)。

同一 RandomSource 的所有 Next、Fill 和分布调用消费同一组 lane 状态及必要的私有原始输出缓存，不建立互不影响的“标量流”和“批量流”。缓存属于当前 run，绝不保存到 Optimizer 或全局。lane 数、宽度选择、缓存大小和尾部排放顺序属于 Plan 的私有设计，须在实现前固定并验证；不得依赖线程、Group 或调用时间选择。

ADR-0021 已替代 ADR-0020 的单组四字状态决定，SPEC-0009 已记录对应局部替代范围。Core 不接入源码生成器，Reflect 仍为标量，ADR-0019 的这些限制继续有效。Core 随机内核直接使用通用 Vector128/256/512 API，禁止 ISA 专属 API 和运行时抽象分派。联合规格已获批准；正式决策见 ADR-0021。

## 信任与责任边界

| 数据或行为 | 责任方 | Core 是否验证 | 违反契约的结果 |
| --- | --- | --- | --- |
| seed 与 run 生命周期 | Core Execution | 每 run 创建 | 不得跨 run 共享 |
| 状态推进与分布 | Core Randomness | 内部正确性测试 | 不得换成未经批准的生成模型 |
| Span 与区间参数 | 调用方/Randomness | 沿用既有验证 | 无效参数在写入和推进前失败 |
| 抽样时机 | Optimizer/策略 | 不代为决定 | 不得通过 Core 优化重排回调 |

## 功能需求

### FR-001：保持随机源与基础采样契约

- 前置条件：有效 run 和调用方拥有的 Span。
- 触发行为：调用 Next 或 Fill。
- 预期结果：保留 SPEC-0009 的 API、每 lane 原始状态转换、半开范围、有界整数无偏性和异常语义；播种扩展为上述 lane 派生规则，不保留旧版本完整输出序列。
- 边界情况：空 Span 不消费状态；极端有限 double 范围、相邻端点、整数全范围和拒绝采样均保持正确。
- 验收标准：每 lane 的状态转换及 Jump 已知答案、边界和异常原子性测试通过；未向量化的映射仍消费同一组新状态。

### FR-002：保持弱序列兼容与分布职责

- 前置条件：相同版本、目标环境、seed、方法序列及参数。
- 触发行为：标量、批量和混合调用。
- 预期结果：重复执行逐位一致；继续不保证不同 Fill 切分、标量/批量、跨版本或跨平台等价。
- 边界情况：StandardNormal 保持静态分布，无跨调用 spare；奇数长度和尾部不得越界。
- 验收标准：固定序列重复测试、正态统计测试和 run/Group 隔离测试通过；不增加未承诺的等价性断言。

### FR-003：有界 SIMD 优化与回退

- 前置条件：Spec 与 Plan 获批准。
- 触发行为：对批量热路径构造候选。
- 预期结果：原始状态推进必须存在实际 SIMD 生产路径，同时报告输出转换和分布的向量化范围；保留同一 lane 模型的无硬件加速和短输入路径。
- 边界情况：不支持硬件的环境使用标量执行同一 lane 算法；任何进一步更换 PRNG、增加独立随机后端或引入 Core 生成器的提议须退回上游审批。
- 验收标准：逐 lane 标量参考验证输出及状态；反汇编证明 XOR、shift/rotate 和整数加法的状态推进实际 SIMD 化，不能仅证明存储或 double 映射向量化。无收益候选删除，并记录拒绝证据。

## 非功能需求

### NFR-001：正确性、分配与性能证据

- 测量方式：自动化测试、BenchmarkDotNet、MemoryDiagnoser 与反汇编；主要长度 32、128，诊断长度 0、1、2、7、8、15、16、31、33、127、129、1024。
- 可接受阈值：采样调用级托管分配为零；新增保留路径必须有同机内核收益和代表性算法端到端证据；单独测量多 lane 播种和首次调用成本，端到端包含每 run 新建随机源；具体速度门槛、统计容差和回退阈值在 Plan 中预先确定。
- 证据类型：记录基线提交、CPU、OS、Runtime、各位宽硬件支持、输入、配置、分配和基线耗时/候选耗时；不以旧 System.Random 迁移收益充当本次 SIMD 收益。每轮测量先展示代码和完整命令，获得用户反馈后运行。

### NFR-002：多 lane 随机质量

- 测量方式：逐 lane 与独立标量参考对照，同时检查 lane 交织输出、相邻 seed、标量/Fill 混合调用、有界整数拒绝路径及正态统计。
- 可接受阈值：状态转换与 Jump 参考逐字一致；不得以播种不相同替代质量验证。Plan 必须预先固定样本量、测试项目和统计阈值，禁止失败后换 seed 重试；较大样本随机质量检验的工具与运行预算在 Plan 中列明。
- 证据类型：已知答案、确定性统计测试及质量检测报告；小样本检查只作为回归证据，不宣称证明随机独立性。

## 职责与替代关系

- 新增概念：仅内部多 lane 状态、初始化 Jump 及必要原始输出缓存；无公共概念。
- 被替代概念：单组四字状态及其标量/Fill 实现；所有基础采样统一消费新的内部状态。
- 必须删除：旧单流状态字段、失去用途的 helper 和失败候选；不保留兼容模式、独立标量流或双后端配置。
- 保留：作为短输入/不支持硬件路径及独立测试参考的标量计算。
- 唯一所属层：Core 拥有采样与状态，Algorithms 拥有抽样布局。

## 成功标准

原始状态推进实际 SIMD 化，契约、统计、状态隔离和零调用级分配通过；每项保留优化具备可追踪的 SIMD 与性能证据。若全部候选无收益，报告结论并由用户决定收束或修订目标，不将“接口已批量化”标记为 SIMD 目标完成。

## 已澄清决定

- 2026-09-06：用户要求四种算法都进一步优化，并接受批量采样造成旧固定 seed 轨迹变化。
- 2026-09-06：用户同意原始 PRNG 状态推进本身 SIMD 化，即使需要调整单流状态模型及替代 ADR。
- 已批准的具体方案为：保留 xoshiro256++，内部 Jump 派生 lane，全部入口共享状态及必要缓存，不公开多流功能。
- 项目作者于 2026-09-06 批准包含本状态方案的联合规格，可制定技术 Plan。
