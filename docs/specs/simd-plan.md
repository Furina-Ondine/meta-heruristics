## 性能门槛与工作量

以下事前门槛及本附件的数值预算、验证负载已由项目作者于 2026-09-15 确认；项目作者于 2026-09-17 在执行前补充了连续计算流的操作划分，并将受限 Vector128 路径门槛调整为不弱于标量。除这项事前修订外，不能在看到数据后降低门槛；整份 Plan 的批准记录仍分别维护：

- 主要维度 D=32、128，每个主要点分别判定。稳态候选调用零新增托管分配；新增持久工作区以每 Optimizer 的载荷字节、数组数量及实测首次分配报告。
- 为覆盖实际二十几到上百维的负载，补充 D=24、25、64、65，分别观察中间规模和不满向量的尾部；与既有诊断点一起按不超过 5% 回退的规则判定，不改变 32/128 的主要验收地位。
- B 相对 A：含采样的局部操作至少 1.10×，完整 run 至少 1.02×。PSO 的初始化 B 以 ResetForRun 局部操作判定；不以不受影响的 Advance 内核判定初始化收益。
- PSO 将初始化批量化 B-init 与整代系数预取 B-coeff 分开计量，再评估二者组合；B-coeff 局部计时包括整代采样、缓冲读写和候选消费，工作区载荷为 16P 字节。算术 C 与同一已选采样布局的 B 对照。
- C 相对 B：算术内核至少 1.10×，完整 run 至少 1.02×；最终保留版本相对 A 的完整 run 也至少 1.02×。不允许随机源或批量化收益掩盖额外算术复杂度无收益。
- 局部操作按一段连续计算流划分，而不按数组读取或中间表达式数量拆分：同一输出在多次读入后连续完成公式、限幅和选择，并最终单次写回，整体计为一次操作。局部基准必须覆盖这段完整数据流及其全部实际读写；不得把其中一个子表达式单独计时后代表整次操作。Bat 的频率驱动速度更新和 PSO 的速度→Clamp→位置双输出均按此口径。
- 受限到 Algorithms `Vector128` 路径的独立性能运行只要求相对同公式标量参考不回退，即加速比至少 `1.00×`；该宽度仍须通过数值、分类、尾部、JIT 和零新增稳态分配门槛。此放宽不指维度 `D=128`，也不降低正常执行环境下 A/B/C 的局部 `1.10×`、完整 run `1.02×` 或诊断回退门槛。
- 相等边界、零扰动、短维度等诊断负载不得出现确认后的超过 5% 回退；软件路径以正确性和分配为硬门槛，不声称硬件加速。
- 使用 BenchmarkDotNet 的 Mean 计算速度比。主要门槛还需基线与候选的报告置信区间支持耗时下降；结果跨越门槛或区间重叠则报告“不确定”，先调查噪声/工作量。不能挑选最快一轮。
- 默认 Release、同一 SDK/Runtime、2 launches、8 warmups、20 measured iterations，MemoryDiagnoser；诊断筛选可用 Short，但不作为最终验收。最终配置、完整命令、源 hash、预计和实际 case 数记录于 Verification。
- 端到端使用 Sphere、Clamp(-5,5)、种群 64、seed 20260905、MaxIterations(10) 与 MaxIterations(100)。Initializer 使用当前基准的逐维有界单值采样；本轮不优化策略实现。每次测量必须进入 OptimizationRunner，计入新 Context/RandomSource（含 Jump）、ResetForRun、Repair/Evaluate 和固定工作量执行。
- 分别测量新建 Optimizer 的首次完整 run，以及预先分配工作区的同 Optimizer 顺序完整 run。后者仍每次创建新 run Context 并 ResetForRun；不能只计 Advance 而标称完整 run。完整 run 的分配无需为零，但必须解释新增工作区与原有运行对象。
- 报告实际迭代数、评估数和 Repair 数。Firefly 的吸引/移动数受轨迹影响，必须额外记录；算术隔离使用相同随机输入与固定吸引事件的内核，不能把不同移动数量解释为每次移动变快。

优先直接 TensorPrimitives，先检查适用性、正确性与上述门槛。没有适用直接操作或未通过门槛时，评估已批准 Plan 范围内的私有融合内核。若 B 无收益，不单独保留 B 或宣称 B 成功；仍可评估组合候选，但最终保留方案须满足 A/C 总门槛和 B/C 算术增量门槛。对 Cuckoo 的强制正态职责迁移若与性能门槛冲突，退回 Spec，不能擅自保留重复分布实现并标为完成。

## 完整求解耗时的报告口径

固定迭代的完整 run 与达到指定精度的求解时间分别报告。前者使用上述相同工作量评价执行成本；后者必须先确定目标函数、维度、种群、目标误差、最大评估预算及 seed 集合，再报告成功率和达到目标的时间/评估数。不能将 10 代或 100 代的固定工作量耗时直接称为收敛到目标精度的时间，也不从微小复制内核推断整体求解加速。本阶段只定义口径，不补测。

## 数值与抽样验证

- 所有纯算术差分显式传入相同样本，避免将 RandomSource 的新流差异计为浮点误差。保持源码括号、乘加次序，不主动使用 FMA、倒数乘法替代除法或自写近似超越函数。局部例外仅为 SPEC-0012 FR-002 已批准评估的 Lévy 分母 Exp(p*Log(x))；适用输入域、Math.Pow 回退及误差门槛见 Cuckoo Plan，不向其他公式推广。
- Bat、PSO、Firefly 的新增逐元素算术，对有限结果使用 `abs(actual-reference) <= 1e-12 + 1e-12*abs(reference)`。还需单独断言布尔分支和选中的状态字段完全一致；零的符号、Infinity 符号和 NaN 分类与参考一致（不要求 NaN payload 一致）。同一参考为有限时，不能接受候选溢出为 Infinity。邻近限幅端点需检查输出仍在合法速度区间。
- Cuckoo 的 Pow 与位置复合误差预算见其 Plan。旧 Firefly 距离归约不改写，保留原有差分和分类测试。
- 全算法测试维度：1、2、7、8、15、16、24、25、31、32、33、64、65、127、128、129、1024；内部内核另测空 Span、精确 in-place、非对齐切片、前后哨兵，禁止无依据使用 LoadAligned。内部方法的等长及允许别名由调用方构造保证，不增加逐块防御验证。
- 批量参考使用最终 SPEC-0010 的实际 L 和 Fill 边界。尾部只取本次 Fill 输出，不用单值 NextDouble 补齐，不缓存 Fill 未返回的尾轮 lane、不把小输入转回另一套随机状态。Plan 明确的预生成样本缓冲按各 Spec 的生命周期消费。修改 Fill 的拆分会改变序列，需要重新审阅 Plan。
- 各 Spec 允许显式布局的跨回调样本预取，当前 Plan 选择 Bat/Cuckoo 单候选批量采样、Cuckoo 逐候选生成索引、Firefly 每次移动 Fill(D)、PSO 整代系数预取。按实际布局验证粒度、角色切片、两套状态路由、尾部有效范围及后续随机状态，不为未采用的预取方案建立验收要求。允许样本重新分配，不要求与旧布局逐值一致；实际回调和状态更新顺序保持。Bat 保留相等区间不采样，Cuckoo 实时读取位置，Firefly 每次距离计算仍使用前次 Repair 后的目标，PSO 保持每粒子一对系数共享。
- 样本缓冲跨 run 复用，无需清零或额外重置。每次读取前完整写入本次有效区间，只读取本次已写入范围；容量余量和取消后未使用的数组内容无需清理。当前布局的消费索引均为循环局部变量。验证先写后读和读取范围，不要求检查旧数组内容已清除。
- 批量采样、Cuckoo 索引映射和算术融合分别设增量对照，再评估组合；各布局计入采样、缓冲写入/读取和候选消费成本，分别报告工作区，不把采样布局收益归给算术 SIMD。
- 同版本同环境固定 seed 重复、同 Optimizer 顺序复用、独立实例并发、不同 RunGroup 拆分与调度、取消和异常测试均需覆盖。测试策略分别消费单值和批量状态，观察后续值及回调事件；只消费单值的策略不会被某次 Fill 直接推进，但从单值迁移到 Fill 会改变相对旧版本的标量消费。
- 记录 `Vector<double>.Count`、Vector.IsHardwareAccelerated、Vector128/256/512 硬件支持以及运行环境。Core 随机宽度与 Algorithms 固定宽度级联分别验证：不能用 DOTNET_MaxVectorTBitWidth 推断已禁用 Algorithms 的 Vector512。通过独立进程限制指令集并记录实际支持；具体开关在测量前核对。
- 正确性运行覆盖实际可用的 128/256/512 路径及无硬件环境。机器不支持的路径标为未实测，不伪装为覆盖。JIT 证据必须显示保留内核的真实向量运算及尾部。
