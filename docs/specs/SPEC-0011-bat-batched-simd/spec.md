## 问题与动机

提交 `819a40c` 的 `BatOptimizer.GenerateCandidate` 在逐维循环中交错执行频率采样、速度限幅、脉冲分支、条件扰动和响度接受判定。SPEC-0009 提供 Fill，但明确将算法批量接入留给独立 Spec。当前循环适合调查批量随机加逐维算术，收益尚未验证。

## 目标

- 降低 Bat 候选生成开销，并以相同工作量的完整 run 证明收益。
- 明确批量抽样造成的轨迹变化及其对调用方 Repair 随机消费的影响。

## 非目标

- 不改变 Options、算法系数、种群布局、选择策略、公共 API 或并行模型。
- 不把 Bat 随机布局和公式放入 Core。

## 架构契合

遵循 ADR-0025：优先直接使用 TensorPrimitives；没有适用直接操作或未通过门槛时再评估 Algorithms 私有融合内核。工作区属于 Optimizer，顺序 run 复用存储但重置逻辑状态；不得缓存随机源跨 run。依赖 SPEC-0010 的最终行为，但可先用当前 Fill 独立验证算法批量化。

## 信任与责任边界

| 数据或行为 | 责任方 | Core 是否验证 | 违反契约的结果 |
| --- | --- | --- | --- |
| Options 与公式 | Bat | 不重复验证 | 沿用构造阶段失败 |
| 随机批次及工作区 | Bat | 否 | 仅按明确布局预取；每次读取前完整写入本次有效区间 |
| Repair/Evaluate | Context/策略 | 沿用现状 | 不得改变调用顺序与计数 |

## 功能需求

### FR-001：候选语义保持

- 前置条件：成功 ResetForRun。
- 触发行为：Advance 生成候选。
- 预期结果：使用本轮新频率更新目标速度并限幅；保留脉冲和响度比较方向、位置选择、衰减公式和代际选择。
- 边界情况：拒绝候选不得污染源速度或状态；相等采样上下界返回常量且不消费对应随机样本。
- 验收标准：给定相同抽样输入的标量公式差分覆盖分支两侧、边界和尾部；数值容差由 Plan 预先列明。

### FR-002：批量抽样与可复现性

- 前置条件：用户接受新旧版本固定 seed 轨迹变化。
- 触发行为：将逐维随机请求组织成候选内或跨候选的显式批次。
- 预期结果：允许候选内重排、跨回调预取随机样本，以及为未选中的分支预生成扰动。Plan 明确粒度、角色切片、标量/批量状态路由、尾部与缓冲生命周期；维持分布与各随机角色独立性，同版本同环境重复执行一致。
- 边界情况：样本预取不得改变实际 Initializer/Repair/Evaluate 的次序、次数或候选状态计算时机；不得提前捕获依赖回调的可变状态。相等区间仍不消费对应样本；同一 run 的后续策略随机数允许随已定义布局变化。
- 验收标准：固定 seed 重复、顺序复用、不同 Group 划分及并发隔离测试通过。

### FR-003：工作区与生命周期

- 前置条件：一个 Group 独占 Optimizer。
- 触发行为：首次及后续 ResetForRun、Advance。
- 预期结果：新增必要缓冲仅首次分配，跨 run 复用且无需清零或额外重置；每次读取前完整写入本次有效区间，只读取本次已写入范围。保留先生成并 Repair 全部候选、再 Evaluate、再选择的现有阶段顺序。
- 边界情况：维度变更、异常后复用及取消继续遵循既有契约。
- 验收标准：回调顺序/次数、状态恢复与分配测试通过。

## 非功能需求

### NFR-001：可验证的性能收益

- 测量方式：候选生成内核和固定迭代完整 run；主要维度 32、128，补充 1、2、7、8、15、16、24、25、31、33、64、65、127、129、1024；覆盖分支与相等边界。
- 可接受阈值：稳态候选调用无新增托管分配；内核和主要端到端负载须有收益，具体门槛在 Plan 固定。记录新增持久工作区大小。未通过候选删除。
- 证据类型：同机 BenchmarkDotNet、分配、实际 SIMD 反汇编；基准配置、完整命令、源 hash 和结果记录于 Verification。
