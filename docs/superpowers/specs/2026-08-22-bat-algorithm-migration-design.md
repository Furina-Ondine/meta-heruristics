# 蝙蝠算法第一波迁移设计

状态：第一版已实现。

## 目标

- 把旧论文仓库 `fix` 分支的连续蝙蝠算法迁移到 `Metaheuristics.Algorithms`。
- 使用当前有状态 `IOptimizer` 生命周期，在 RunGroup 内复用主要工作区。
- 支持 Core 的显式 seed、最小化/最大化、约束比较、取消和评估计数。
- 用回归测试固定旧审计已经确认的错误修复。

## 来源审计

旧仓库 `fix` 分支确认并修复了三项 Bat 专属问题：初始种群未评估；历史最优保存种群引用而被双缓冲覆写；候选使用旧频率并修改源速度。迁移版不复制旧基础类、泛型适应度/解对象、`Random.Shared` 或算法内位置上下界。

原论文给出频率、速度、位置、局部随机游走、响度和脉冲发射率的基础更新关系。旧论文实验实现采用逐维频率、响度和脉冲率，是一个已经进入历史实验的变体；第一波迁移保留该变体，避免在迁移同时重新定义算法。

## 公共表面

- `BatOptimizerOptions`：不可变配置记录。
- `BatOptimizer`：RunGroup 独占的有状态算法实例。
- 可选 `ICandidateInitializer`：为默认有限边界均匀初始化提供替代策略。

位置范围只由 `ContinuousProblem` 定义。算法构造阶段验证全部独立参数；问题维度和边界在 `ResetForRun` 时验证。

## 状态与更新

每个 Optimizer 创建两组 `BatState[]`，每个状态持有六条 `double[]` 和一个 `Evaluation`。一代候选只写目标缓冲；选择后交换状态对象引用。历史最优拥有独立位置数组。

`ResetForRun` 只初始化当前源种群，目标缓冲在下一次 `Advance` 中会被完整覆盖。正常的后续 Reset 不重新分配种群、状态或各维数组。

候选生成沿用 `fix` 分支语义：按逐维新频率计算目标速度；局部搜索和坐标接受由源脉冲率、响度控制；评估后再与对应 incumbent 严格比较。最终比较统一委托给 Core。

## 测试边界

- 初始完整评估及历史最优；
- 最小化、最大化与约束可行性；
- 相同 seed 确定性和独立实例并发隔离；
- Reset 工作区引用复用和不同维度拒绝；
- 新频率使用、候选拒绝时源速度隔离、历史最优快照；
- 默认有限边界和自定义无界初始化；
- 固定 seed 的标准 Sphere 改善。

最终公共用法以 [`docs/api/algorithms.md`](../../api/algorithms.md) 为准，迁移顺序理由见 [ADR-0011](../../decisions/0011-bat-first-algorithm-migration.md)。
