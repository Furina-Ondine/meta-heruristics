# ADR-0017: 仓库私有 SIMD 增量源码生成

## 状态

Superseded by [ADR-0019](0019-scalar-reflect-and-algorithm-only-simd-generation.md).

## 背景

Core 的 Reflect Repair 与 Algorithms 的 PSO、Firefly 私有向量算术都使用 ADR-0016 批准的 `Vector512<T> → Vector256<T> → Vector128<T> → scalar` 固定宽度级联。运行时所有权正确地分别保留在 Core 与 Algorithms，但硬件门、完整块条件、索引推进、宽度缩窄、标量尾部以及部分三宽度块体由多个方法重复手写。

统一修改宽度、元素计数、加载/存储或未来经批准的 SIMD 策略时，重复实现会产生维护成本和漂移风险。把循环提取为运行时 delegate、接口、静态抽象 kernel 或跨程序集 Helper 会增加分派、状态传递或 JIT 内联不确定性，并可能把 Algorithms 的实现机制错误放入 Core，不能满足 SPEC-0006 的零运行时开销和职责边界。

源码生成器只能向当前编译添加源代码，不能重写已有方法。因此生成输入还必须同时保证：消费方公式可读且仍由其所属层维护；输出能够成为完整、直接展开的方法；构建失败可定位；生成产物不会成为第二份需要手工同步的权威源码。

## 决策

- 在 `eng` 下建立仓库私有 Roslyn `IIncrementalGenerator`，由 Core 与 Algorithms 以 analyzer 形态在编译期引用；生成器程序集不进入运行时依赖、发布包或公共 API。
- 生成器只读取消费项目显式列出的受限 AdditionalFiles 模板。每个模板完整描述消费方方法，并包含恰好一个固定宽度模板块；生成器把该块按 512、256、128 位直接内联展开，再保留模板显式提供的标量尾部和返回逻辑。
- 模板块只允许当前向量泛型类型、对应静态向量 API、位宽后缀、元素计数和硬件可用性等有限占位符。生成器按语法节点替换，不进行无边界文本宏、不推导业务公式、不扫描运行时类型、不访问网络或环境状态。
- 生成后的类型和成员保持消费程序集私有。Core 继续拥有 Repair、边界、Reflect mask、危险 lane 与标量参考；Algorithms 继续拥有 PSO/Firefly 公式、归约和工作区。生成器只拥有机械展开规则。
- 生成 `.cs` 默认只存在于编译器和 `obj`，不提交源码控制；相同输入必须产生确定、稳定且可审查的输出，并通过仓库相对行映射和编译诊断定位模板。
- 首期只迁移现有 `double` 生产路径。`float`、`int` 和内存对齐仅验证扩展边界与错误诊断；任何新生产 specialization 或加载策略必须由后续 Spec、数值测试和性能证据批准。
- 替换前后必须比较 IL/JIT 结构、分配、局部与端到端 BenchmarkDotNet。生成路径出现额外调用、分派、分配或可确认性能回退时，删除候选接入并保留当前手写实现，不保留运行时开关或双生产路径。

本决策补充而不替代 ADR-0016。ADR-0016 继续定义 Algorithms 可采用固定宽度级联的运行时边界、宽度顺序、TensorPrimitives 优先级和性能准入；本决策只统一已批准级联的编译期机械展开。

## 替代方案

- Core 运行时 Helper 加 delegate、接口或静态抽象 kernel：不采用。它不能保证没有额外分派或内联损失，并会扩大 Core 的运行时职责。
- 通过 `Compile Link` 把共享 `.cs` 编译进两个程序集：不采用。C# 无法用一个普通零成本抽象同时表达三种固定宽度向量类型和不同块体；最终仍会复制公式或引入调用边界。
- 构建前脚本或通用模板工具：不采用。它需要额外处理 IDE、增量/并行构建、陈旧输出与清理；提交生成文件还会建立模板和产物双权威。
- 继续手写所有级联：不采用。当前已跨两个运行时项目和多个热路径重复，无法统一未来的机械 SIMD 模式修改。
- 建立可表达任意 C# 的宏或 SIMD DSL：不采用。它会形成新的编译器语言、诊断和长期兼容职责，超过当前有限重复的收益。

## 后果

仓库增加一个编译期生成器项目、一个生成器测试项目、集中锁定的 Roslyn 编译期依赖和受限模板格式。维护者需要能够查看生成源和理解诊断；生成器本身必须有 golden、负面、确定性和增量测试。

运行时项目不会增加共享 SIMD 程序集、公开后端、策略对象、状态或用户配置。生成的完整方法可以与当前手写展开保持相同控制流；是否真正零开销仍由目标 Runtime/JIT 的反汇编和基准决定，不能仅根据“编译期生成”推断。

消费方模板成为公式与标量尾部的唯一手写权威，生成 `.cs` 不提交。通过性能门槛后必须删除旧手写展开；未通过时必须删除对应生成接入，避免长期双路径。

## 重新评估条件

若受限模板必须解析任意 C#、需要运行时 callback/接口、无法直接生成完整方法、必须提交生成产物、需要 ISA 专属 API、更多向量宽度、公共计算后端、生产 `float`/`int`/对齐策略，或目标 SDK 提供更简单且经端到端证明的零分配 TensorPrimitives 表达，则新增 ADR 重新评估。本 ADR 不原地扩大范围。
