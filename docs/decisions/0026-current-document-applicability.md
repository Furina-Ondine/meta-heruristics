# ADR-0026: 文档执行历史与当前适用性分离

## 状态

Accepted

2026-09-18，项目作者批准工程规范评估中的文档有效性、当前系统入口和证据治理改进。本记录仅替代 [ADR-0014](0014-spec-driven-change-governance.md) 将 Approved/Implemented 直接等同于现行规格的权威判定部分；其 SDD 阶段、两次批准门、四件套、职责清理、XML 契约和冲突处理继续有效。

## 背景

历史 Spec 的 Implemented 状态说明当时通过验收，不能说明所有需求今天仍有效。Reflect 的旧 SIMD 规格与后续标量规格同时显示 Implemented，ADR 整篇替代又经常保留其中一部分约束，使当前规则依赖读者从历史链中重建。

## 决策

- Spec 的执行状态与当前适用性独立。适用性使用 Current、Partial、Superseded；部分替代精确记录旧条款、变化范围、当前接替位置及保留内容。
- ADR 保留 Accepted、Superseded、Rejected。Accepted 记录发生部分替代时在状态区显著说明范围；只有整篇不再承载现行决策时标为 Superseded。不把部分替代简化成整篇失效。
- 不改变含义的错字、链接与表达可以原地修正；不改变边界的解释和证据可以带日期补充。改变允许/禁止行为、责任、约束或选择时新增 ADR，尽量一个记录只处理一个可独立变化的决策。历史已批准补充保留原貌，不据此默许继续追加新决策。
- 架构概览作为当前系统的导航和摘要，具体权威内容仍在 ENGINEERING、当前适用的 Spec/ADR 与源码 XML；不新增与这些来源并行的总规格。
- 索引优先呈现当前有效内容，历史记录按需追溯。历史数量不设上限，不按编号推断优先级，不为减少数量而删除历史证据。
- 验证工具检查显式适用性与索引一致性、替代范围的基本结构及链接；自然语言中的语义完整性仍需人工审查，工具通过不代表所有架构冲突已经消失。

## 替代方案

- 整篇替代并让读者追溯继承链：会把当前规则分散到已失效文档。
- 重写全部历史为最新设计：丢失当时批准与验收的依据。
- 新增一份复制所有契约的万能文档：扩大同步成本，违反单一内容来源原则。

## 后果

增加少量适用性元数据和定向校验；保留现有审批阶段与历史验收记录。现有文档按已经批准的替代事实补记范围，不利用本次整理批准新的运行时行为。

## 重新评估条件

当逐条替代关系已无法以短表表达，或当前入口仍要求大量历史追溯时，评估按功能维护独立的现行规格；不能仅为减少文件数取消批准与追踪要求。
