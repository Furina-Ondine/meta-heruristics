# ADR-0006: 评估、性能与可复现性

## 状态

状态：Accepted

## 背景

目标函数通常是优化热路径。首版需要先定义可靠的评估契约，再在不改变结果语义的前提下优化吞吐量。

## 决策

- 单点同步评估是基础契约；本机同步批量评估是可选快速路径。
- 每个 run 使用独立种子和随机流；禁止全局随机状态。
- run 的随机序列不随实验批次的并发度变化而改变。
- 相同库版本、运行时和执行设置下，相同种子产生相同结果。
- 性能改动必须有 BenchmarkDotNet 数据或分配分析支撑，并保留清晰、正确的基础路径。
- 首版不引入远程、集群或 GPU 评估后端。

## 替代方案

- 以异步或并行评估作为唯一契约：增加使用和实现成本，掩盖基础语义问题。
- 共享全局随机流：实现简单，但破坏运行隔离和可复现性。
- 无基准直接优化：难以证明收益，容易损害正确性。

## 后果

调用方只需实现单点评估即可；批量实现可按需提供，性能优化受数据和确定性约束。更高性能的后端须另行定义边界和生命周期。

## 重新评估条件

当基准证明批量、并行或其他计算后端成为稳定需求时，通过新 ADR 重新评估。
