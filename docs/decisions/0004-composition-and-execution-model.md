# ADR-0004: 组件构造与运行模型

## 状态

状态：Accepted

## 背景

算法、问题和评估器需要灵活组合，同时每次运行必须隔离状态，批量实验还需安全、可复现地重复构造组件。

## 决策

- 用户选择并装配问题、算法和策略；库负责启动、协调、取消和释放运行生命周期。
- 单次运行接收调用方创建的实例；批量实验接收强类型工厂，为每个 run 创建隔离实例。
- `Optimizer` 保存可复用的算法定义和不可变参数，并为每次运行创建专属 `Session`；`Runner` 获得并持有该 `Session`，驱动初始化、迭代、停止和结果复制，结束时释放它。
- 禁止全局字符串注册中心、服务定位器、按字符串类型名恢复组件，以及跨运行共享可变状态。

## 替代方案

- 库内置组件注册和对象构造：调用表面更短，但隐藏依赖并限制用户扩展。
- 所有场景只传实例：单次运行简单，但批量并发时难以保证隔离。
- 复用可变会话或全局状态：减少分配，却破坏并发安全和可复现性。

## 后果

依赖和对象所有权保持显式，单次调用简洁，批量实验可隔离运行；用户需要承担组件选择与工厂定义，`Session` 本身不保证线程安全。

## 重新评估条件

当公开运行语义、状态所有权或跨进程执行需求发生变化时，通过新 ADR 重新设计。
