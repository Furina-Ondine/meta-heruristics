# ADR-0025: 直接 TensorPrimitives 优先与算法基准执行

## 状态

Accepted

替代 [ADR-0022](0022-batched-algorithm-simd-fusion.md)。2026-09-14，项目作者明确要求优先直接 TensorPrimitives，并取消每次基准运行前展示代码、命令和等待反馈的要求。

## 背景

四种算法的 SIMD 规格已批准，技术 Plan 正在审阅。Bat GenerateCandidate 的逐维分支需要通过实验判断 SIMD 的实际收益；向量化是候选方案，不是预定的实施结论。项目作者调整了候选优先级与基准执行安排。

## 决策

- Algorithms 优先审查直接 TensorPrimitives 调用。有适用直接操作时先验证；没有适用直接操作或未通过数值/性能门槛时，评估 Algorithms 私有融合内核。
- 算法无状态算术继续使用通用 Vector512/256/128 完整块级联及标量尾部；现有模板展开只服务 Algorithms。
- PSO 可以比较速度、限幅和位置更新融合内核与现有生产路径，通过数值及局部、端到端门槛后才替代。
- 不使用 ISA 专属算法 API，不引入公开 SIMD 后端、配置、SoA 布局、共享缓冲或跨 Optimizer 状态。
- 批量抽样允许已批准的旧 seed 轨迹变化，但不改变随机角色含义和相关结构：PSO 每粒子共享两个系数，Firefly 保持吸引顺序与每次移动后 Repair。
- 保持公共 API、Repair/Evaluate 时点、状态隔离、数值分类和现有可复现性边界。
- 在用户授权的实验或 Approved Plan 范围内自主运行基准并按结果推进，不设逐轮展示或反馈门。记录源 hash、完整命令、配置、实际 case 数、环境、时间和分配，保留可复核证据。
- 具体实现仍受 Spec/Plan 批准范围约束；取消逐轮运行确认不等于批准所有算法实现。用户单独要求的诊断实验按明确范围执行，其结果不能代替生产接入验收。
- Bat 的分支、候选两边计算和多字段写回必须以代表性分支分布实验比较；失败候选删除，不预先承诺 SIMD 收益。

## 替代方案

- 保持原逐轮测量确认：项目作者已取消。
- 一律采用私有 SIMD：不采用，直接 TensorPrimitives 仍优先。
- 因分支多而直接拒绝 SIMD：不采用，先收集同输入数值与性能证据。

## 后果

基准可以连续执行而无需逐轮等待；性能结论仍须有局部与完整 run 证据。四份 Plan 继续各自审批，已批准实验和生产接入的边界分别记录。无收益的生产候选不保留切换开关。

## 重新评估条件

需要改变公开能力、随机角色、回调顺序、布局、ISA 边界或性能验收原则时重新审查 Spec/ADR。
