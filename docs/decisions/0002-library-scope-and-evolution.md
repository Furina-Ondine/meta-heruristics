# ADR-0002: 库范围与演进顺序

## 状态

状态：Accepted

## 背景

首版需要先验证核心运行模型和算法实现，同时为后续目标值及解表示扩展保留清晰路径，避免一次性建立未经使用的通用抽象。

## 决策

- 首版候选位置固定为连续 `double` 向量，单目标值固定为标量 `double`。
- 后续依次引入：由 Objective Policy 驱动的泛型单目标值、多目标值、二进制表示、排列表示。
- 泛型单目标值不要求实现 `IComparable<T>`；Objective Policy 显式定义排序方向、比较、等价性及算法所需统计能力。
- 首版只支持进程内、本机 CPU 执行，不建设远程、集群或 GPU 后端。

## 替代方案

- 首版即泛化候选与目标值：灵活但会让尚未验证的扩展需求进入核心 API。
- 以 `IComparable<T>` 约束目标值：只能表达自然顺序，无法完整承载优化方向和统计语义。
- 预建远程、集群或 GPU 抽象：对个人实验场景收益不足，却显著扩大系统边界。

## 后果

首版 API 和热路径保持简单；新增目标类型或解表示需要按既定顺序扩展并补充 ADR，不能承诺现有算法自动适配未来表示。

## 重新评估条件

当前阶段形成稳定实现和测试后，或出现经基准与用例证明的后端需求时，通过新 ADR 推进下一阶段。
