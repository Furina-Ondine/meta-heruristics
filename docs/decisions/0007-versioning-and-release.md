# ADR-0007: 版本与发布

## 状态

状态：Accepted

## 背景

多个运行时包需要保持兼容关系，用户也需要从版本号判断升级风险。本 ADR 是统一版本和锁步发布规则的唯一权威记录。

## 决策

- 采用 SemVer 2.0.0。
- `Metaheuristics.Core`、`Metaheuristics.Algorithms` 和 `Metaheuristics.Experiments` 使用同一版本号并锁步发布；即使某包没有代码变化，也发布相同版本。
- `1.0.0` 前，破坏性变化至少提升 `MINOR` 并在发布说明中记录。
- `1.0.0` 后，`MAJOR` 表示不兼容变化，`MINOR` 表示向后兼容的新功能，`PATCH` 表示向后兼容的缺陷修复。
- 预发布版本使用 `alpha`、`beta`、`rc` 等 SemVer 标识；纯文档或仓库维护不产生包版本。

## 替代方案

- 各包独立版本：可减少无关发布，但会增加兼容矩阵和维护成本。
- 日历版本：便于表达发布时间，但不能直接表达 API 兼容性。

## 后果

包、文档和发布说明拥有统一的兼容性信号，发布流程更简单；新增可发布包必须通过新 ADR 明确其版本关系。

## 重新评估条件

当包拆分、发布渠道或兼容性承诺发生变化时，通过新 ADR 替代本决策。
